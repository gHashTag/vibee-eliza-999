# 🔧 Решение ошибок `TIMEOUT` в GramJS

## 📋 Описание проблемы

Ошибки `TIMEOUT` возникают в библиотеке GramJS при получении обновлений от Telegram. Это **нормальное поведение** для long-polling соединений и не является критической ошибкой.

## 🔍 Причины

1. **Long-polling таймауты** - Telegram сервер закрывает соединение после периода неактивности
2. **Сетевые задержки** - временные проблемы с сетью
3. **Переподключение** - GramJS автоматически переподключается при таймаутах

## ✅ Решения

### 1. Автоматическая обработка (уже реализовано)

Система автоматически:

- ✅ Подавляет логирование ошибок `TIMEOUT` через кастомный Logger
- ✅ Обрабатывает unhandled rejections с фильтрацией таймаутов
- ✅ Увеличивает таймауты до 10 секунд
- ✅ Настраивает retry логику (3 повтора с задержкой 1 сек)

### 2. Конфигурация таймаутов

Таймауты настроены в `mtproto.adapter.ts`:

```typescript
this.client = new TelegramClient(session, this.apiId, this.apiHash, {
  connectionRetries: 5,
  requestRetries: 3,
  timeout: 10000, // 10 секунд
  retryDelay: 1000, // 1 секунда между повторами
  logger: new Logger("error"), // Только error логи
});
```

### 3. Если ошибки всё равно появляются

Если ошибки `TIMEOUT` всё равно появляются в логах:

1. **Проверьте сеть** - возможны проблемы с подключением к Telegram
2. **Увеличьте таймаут** - измените `timeout: 10000` на большее значение (например, `30000`)
3. **Проверьте сессию** - возможно, сессия устарела и нужно переподключиться

## 🛡️ Технические детали

### Глобальный обработчик ошибок

Система добавляет обработчик `unhandledRejection` для фильтрации таймаутов:

```typescript
process.on("unhandledRejection", (reason: any) => {
  // Подавляем TIMEOUT ошибки из GramJS updates.js
  if (
    errorMessage.includes("TIMEOUT") ||
    reason?.stack?.includes("telegram/client/updates.js")
  ) {
    return; // Не логируем
  }
  // Логируем только реальные ошибки
});
```

### Logger уровень

Используется `Logger("error")` для подавления warning/debug логов от GramJS.


## 💡 Рекомендации

1. **Не беспокойтесь о TIMEOUT** - это нормальное поведение для long-polling
2. **Мониторьте реальные ошибки** - они будут логироваться без фильтрации
3. **Проверяйте подключение** - если ошибки не связаны с TIMEOUT, это может быть проблема сети

## 🔍 Диагностика

### Проверить, что обработка работает

В логах не должно быть повторяющихся `TIMEOUT` ошибок. Если они есть:

1. Проверьте, что код обновлён
2. Перезапустите агентов: `bun dev`
3. Проверьте, что используется последняя версия кода

### Проверить подключение

```bash
# Проверить логи на реальные ошибки (не TIMEOUT)
tail -f logs/*.log | grep -v TIMEOUT | grep -v timeout
```
