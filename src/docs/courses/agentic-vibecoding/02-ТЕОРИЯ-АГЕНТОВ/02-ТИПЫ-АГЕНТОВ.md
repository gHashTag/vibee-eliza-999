## 🗺️ КАРТА 5 ТИПОВ АГЕНТОВ

```
Простота ←────────────────────────────────→ Сложность
Скорость ←────────────────────────────────→ Интеллект

1. Simple Reflex         (Термостат, датчик движения)
   └─ IF-THEN правила

2. Model-Based Reflex    (Roomba, противоугонная система)
   └─ Внутренняя модель мира

3. Goal-Based           (GPS навигатор, шахматный AI)
   └─ Планирование для достижения цели

4. Utility-Based        (AlphaGo, рекомендательные системы)
   └─ Максимизация функции полезности

5. Learning            (ChatGPT, AlphaZero, беспилотные авто)
   └─ Обучение из опыта
```

## 1️⃣ SIMPLE REFLEX AGENTS (Простые рефлексивные агенты)

### 📖 ОПРЕДЕЛЕНИЕ

Агент, который **реагирует ТОЛЬКО на текущее восприятие**, без учета истории.

**Формула:**

```
Действие = f(Текущее_восприятие)
```

**Нет памяти**, нет модели мира, нет планирования.

---

### 🧠 КАК РАБОТАЕТ

```
┌──────────────┐
│  Сенсоры     │ → [Текущее восприятие]
└──────────────┘
       ↓
┌──────────────────────────────┐
│  IF-THEN Правила             │
│  IF temp < 22 THEN heat_on   │
│  IF obstacle THEN turn       │
└──────────────────────────────┘
       ↓
┌──────────────┐
│  Актуаторы   │ → [Действие]
└──────────────┘
```

---

### 💡 ПРИМЕРЫ

#### Пример 1: Термостат

**Восприятие:** Температура = 18°C
**Правило:** IF temp < 22°C THEN heat_on
**Действие:** Включить отопление

---

#### Пример 2: Датчик движения (автоматический свет)

**Восприятие:** Движение обнаружено = True
**Правило:** IF motion THEN light_on
**Действие:** Включить свет

---

#### Пример 3: Автоматическая дверь

**Восприятие:** Человек перед дверью = True
**Правило:** IF person_near THEN door_open
**Действие:** Открыть дверь

---

### ✅ КОГДА ИСПОЛЬЗОВАТЬ

**Идеально для:**

- ✅ Простые, предсказуемые окружения
- ✅ Мгновенная реакция критична (миллисекунды)
- ✅ Нет необходимости в памяти или планировании
- ✅ Дешевые устройства (IoT сенсоры)

**Примеры задач:**

- Термостаты
- Датчики движения
- Автоматические двери
- Светофоры (простые)

---

### ❌ ОГРАНИЧЕНИЯ

**Проблема 1: Нет памяти**

```
Ситуация: Робот застрял в углу
Восприятие: Стена впереди
Действие: Повернуть на 90°
Восприятие: Стена впереди (опять!)
Действие: Повернуть на 90°
→ БЕСКОНЕЧНЫЙ ЦИКЛ (нет памяти о предыдущих поворотах)
```

**Проблема 2: Нет планирования**

```
Задача: Робот должен пропылесосить 2 комнаты
Simple Reflex: Будет ходить случайно, может пропустить углы
Не понимает ЦЕЛЬ "покрыть все пространство"
```

**Проблема 3: Не работает в частично наблюдаемых средах**

```
Пример: Покер (не видно карт противника)
Simple Reflex: Нельзя играть без знания скрытой информации
```

## 2️⃣ MODEL-BASED REFLEX AGENTS (Рефлексивные агенты с моделью)

### 📖 ОПРЕДЕЛЕНИЕ

Агент, который **поддерживает внутреннюю модель мира**, обновляемую при каждом восприятии.

**Формула:**

```
Состояние = update(Состояние, Действие, Восприятие)
Действие = f(Состояние)
```

**Есть ПАМЯТЬ** (внутреннее состояние), но все еще нет планирования.

---

### 🧠 КАК РАБОТАЕТ

```
┌──────────────┐
│  Сенсоры     │ → [Восприятие]
└──────────────┘
       ↓
┌──────────────────────────────┐
│  Обновление модели           │
│  State = f(State, Percept)   │
└──────────────────────────────┘
       ↓
┌──────────────────────────────┐
│  IF-THEN Правила             │
│  (на основе State)           │
└──────────────────────────────┘
       ↓
┌──────────────┐
│  Актуаторы   │ → [Действие]
└──────────────┘
```

---

### 💡 ПРИМЕРЫ

#### Пример 1: Roomba (Робот-пылесос)

**Внутренняя модель:**

- Карта помещения (частично исследованная)
- Позиция робота (x, y, угол)
- Покрытие (какие области убраны)

---

#### Пример 2: Противоугонная система авто

**Внутренняя модель:**

- Состояние дверей (открыты/закрыты)
- Состояние сигнализации (вкл/выкл)
- История событий (последние 10 событий)

---

#### Пример 3: Шахматный робот (механический)

**Внутренняя модель:**

- Позиция всех фигур на доске
- История ходов
- Чей ход

**Почему Model-Based:**

- Доска не всегда полностью видима (робот видит только часть)
- Нужно отслеживать состояние (где какая фигура)

---

### ✅ КОГДА ИСПОЛЬЗОВАТЬ

**Идеально для:**

- ✅ Частично наблюдаемые окружения
- ✅ Нужна память о прошлом
- ✅ Окружение меняется со временем
- ✅ Действия агента влияют на будущие восприятия

**Примеры задач:**

- Роботы-пылесосы
- Системы умного дома
- Навигация роботов
- Мониторинг безопасности

---

### ❌ ОГРАНИЧЕНИЯ

**Проблема 1: Нет целей**

```
Roomba не ЗНАЕТ, что цель — "убрать ВСЮ комнату"
Он просто следует правилам: "Если не убрано → иди туда"
Не оптимизирует путь для быстрого покрытия
```

**Проблема 2: Нет планирования**

```
Шахматный робот НЕ ДУМАЕТ наперед:
"Если сделаю ход A, противник сделает B, я сделаю C → победа"
Просто следует правилам: "Если король под угрозой → защитить"
```

## 3️⃣ GOAL-BASED AGENTS (Целевые агенты)

### 📖 ОПРЕДЕЛЕНИЕ

Агент, который **планирует последовательность действий** для достижения **явной цели**.

**Формула:**

```
Действие = search(Состояние, Цель, Модель_мира)
```

**Есть:** Память + Модель мира + **ЦЕЛЬ** + Планирование.

---

### 🧠 КАК РАБОТАЕТ

```
┌──────────────┐
│  Сенсоры     │ → [Восприятие]
└──────────────┘
       ↓
┌──────────────────────────────┐
│  Обновление состояния        │
└──────────────────────────────┘
       ↓
┌──────────────────────────────┐
│  Цель                        │
│  "Достичь точки (10, 5)"     │
└──────────────────────────────┘
       ↓
┌──────────────────────────────┐
│  Поиск плана (A* search)     │
│  [действие1, действие2, ...]│
└──────────────────────────────┘
       ↓
┌──────────────┐
│  Актуаторы   │ → [Выполнить действие1]
└──────────────┘
```

---

### 💡 ПРИМЕРЫ

#### Пример 1: GPS Навигатор

**Цель:** Доехать от точки A (Москва, Красная площадь) до точки B (Петербург, Эрмитаж).

---

#### Пример 2: Шахматный AI (примитивный)

**Цель:** Поставить мат королю противника.

---

#### Пример 3: Робот-доставщик на складе

**Цель:** Доставить товар X на станцию упаковки.

---

### ✅ КОГДА ИСПОЛЬЗОВАТЬ

**Идеально для:**

- ✅ Есть четкая цель (точка назначения, победа в игре)
- ✅ Нужно планирование (несколько шагов)
- ✅ Окружение предсказуемо (можно симулировать результаты действий)
- ✅ Критична оптимальность пути

**Примеры задач:**

- GPS навигация
- Робототехника (сборка, доставка)
- Игры (шахматы, го)
- Планирование расписаний

---

### ❌ ОГРАНИЧЕНИЯ

**Проблема 1: Только бинарная цель (достигнута vs не достигнута)**

```
Пример: Шахматы
Goal-Based: Цель = "поставить мат"
Проблема: Не различает "мат через 1 ход" vs "мат через 50 ходов"
Обе ситуации = "цель достигнута", но первая ЛУЧШЕ
```

**Проблема 2: Нет оптимизации полезности**

```
Пример: Доставка
Goal-Based: Доставить за 30 минут
Что если можно доставить за 10 минут? Агент не оптимизирует время.
```

**Решение:** → **Utility-Based Agents**

---

## 4️⃣ UTILITY-BASED AGENTS (Агенты с функцией полезности)

### 📖 ОПРЕДЕЛЕНИЕ

Агент, который **максимизирует функцию полезности** (utility function), оценивающую "насколько хорошо" каждое состояние.

**Формула:**

```
Действие = argmax( Expected_Utility(Действие) )
```

**Отличие от Goal-Based:**

- Goal: Цель достигнута? (Да/Нет)
- Utility: **Насколько хорошо** достигнута цель? (Число от 0 до 100)

---

### 🧠 КАК РАБОТАЕТ

```
┌──────────────┐
│  Сенсоры     │ → [Восприятие]
└──────────────┘
       ↓
┌──────────────────────────────┐
│  Обновление состояния        │
└──────────────────────────────┘
       ↓
┌──────────────────────────────┐
│  Функция полезности          │
│  U(состояние) → число        │
└──────────────────────────────┘
       ↓
┌──────────────────────────────┐
│  Выбрать действие            │
│  max( U(результат(a)) )      │
└──────────────────────────────┘
       ↓
┌──────────────┐
│  Актуаторы   │ → [Действие]
└──────────────┘
```

---

### 💡 ПРИМЕРЫ

#### Пример 1: AlphaGo (Игра в го)

---

#### Пример 2: Рекомендательная система (Netflix)

---

#### Пример 3: Беспилотный автомобиль (упрощенно)

---

### ✅ КОГДА ИСПОЛЬЗОВАТЬ

**Идеально для:**

- ✅ Нужна оптимизация (не просто "достичь цели", а "достичь ЛУЧШЕ")
- ✅ Множественные критерии (безопасность + скорость + комфорт)
- ✅ Неопределенность (вероятностные исходы)
- ✅ Трейдоффы (скорость vs безопасность)

**Примеры задач:**

- Игры (шахматы, го)
- Рекомендательные системы
- Финансовый трейдинг
- Беспилотные авто
- Медицинская диагностика

---

### ❌ ОГРАНИЧЕНИЯ

**Проблема 1: Сложность вычислений**

```
Пример: AlphaGo
Для одного хода делает 10,000+ симуляций
Требует мощные GPU/TPU
Невозможно на слабых устройствах
```

**Проблема 2: Дизайн функции полезности**

```
Вопрос: Как ТОЧНО задать "безопасность" автомобиля?
- Расстояние до препятствия?
- Вероятность столкновения?
- Серьезность возможных повреждений?

Неправильная функция → плохое поведение агента
```

**Проблема 3: Не обучается**

```
Функция полезности ФИКСИРОВАНА (задана программистом)
Если окружение меняется → функция устаревает
Пример: Рекомендательная система НЕ адаптируется к новым трендам
```

**Решение:** → **Learning Agents**

## 5️⃣ LEARNING AGENTS (Обучающиеся агенты)

### 📖 ОПРЕДЕЛЕНИЕ

Агент, который **улучшает свою производительность** путем **обучения из опыта**.

**Формула:**

```
Политика_{t+1} = update(Политика_t, Опыт)
```

**Ключевое отличие:** Агент **НЕ статичен** — он **эволюционирует**.

---

### 🧠 АРХИТЕКТУРА LEARNING AGENT

```
┌─────────────────────────────────────┐
│        LEARNING AGENT               │
│                                     │
│  ┌──────────────┐  ┌─────────────┐ │
│  │ Performance  │  │  Learning   │ │
│  │  Element     │←─│  Element    │ │
│  └──────────────┘  └─────────────┘ │
│         ↑ ↓              ↑          │
│  ┌──────────────┐  ┌─────────────┐ │
│  │   Critic     │  │   Problem   │ │
│  │              │  │  Generator  │ │
│  └──────────────┘  └─────────────┘ │
└─────────────────────────────────────┘
         ↑     ↓
   Восприятие  Действия
```

**4 компонента:**

1. **Performance Element** — выполняет действия (как в предыдущих типах)
2. **Learning Element** — улучшает Performance Element на основе обратной связи
3. **Critic** — оценивает качество работы (Reward/Penalty)
4. **Problem Generator** — предлагает новые эксперименты (исследование vs эксплуатация)

---

### 🧠 КАК РАБОТАЕТ

---

### 💡 ПРИМЕРЫ

#### Пример 1: ChatGPT (Reinforcement Learning from Human Feedback)

**Как обучается:**

1. **Предобучение (Pre-training):**

   - Обучение на текстах из интернета (миллиарды токенов)
   - Цель: Предсказать следующее слово

2. **Обучение с учителем (Supervised Fine-Tuning):**

   - Люди пишут примеры "хороших ответов"
   - Модель учится имитировать

3. **Обучение с подкреплением (RLHF):**
   - Critic (Reward Model): Люди оценивают ответы (1-5 звезд)
   - Learning Element: Модель максимизирует рейтинг

**Почему Learning Agent:**

- ✅ Не запрограммирована заранее (обучилась из данных)
- ✅ Улучшается с опытом (RLHF итерации)
- ✅ Адаптируется к новым задачам (few-shot learning)

---

#### Пример 2: AlphaZero (Игра в шахматы/го/сеги)

**Как обучается:**

**Ключевые этапы:**

- Начинает с **случайных ходов** (не знает правил)
- Играет **миллионы игр** сам с собой
- **Обучается** на каждой игре (что привело к победе/поражению)
- Через 4 часа обучения — **сильнее любого человека** в шахматы

**Почему Learning Agent:**

- ✅ Самообучается (без примеров от людей)
- ✅ Эволюционирует (первая версия — слабая, последняя — чемпион)
- ✅ Обобщает стратегии (работает на шахматы, го, сеги)

---

#### Пример 3: Tesla Autopilot (Supervised Learning)

**Как обучается:**

1. **Сбор данных:**

   - Миллионы часов вождения от реальных водителей
   - Камеры записывают (изображение, действие водителя)

2. **Обучение нейросети:**

   ```python
   for (image, steering_angle) in training_data:
       predicted_angle = neural_network(image)
       loss = (predicted_angle - steering_angle)²
       neural_network = update_weights(loss)
   ```

3. **Оценка (Critic):**
   - Безопасные мили без отключения автопилота
   - Аварии → негативная обратная связь

**Почему Learning Agent:**

- ✅ Учится на примерах (supervised learning)
- ✅ Улучшается с каждой новой милей (обновления каждые 2 недели)
- ✅ Адаптируется к новым сценариям (дождь, снег, ночь)

---

#### Пример 4: Spam Filter (Gmail)

**Как обучается:**

**Почему Learning Agent:**

- ✅ Учится на действиях пользователя (Critic: пометка спама)
- ✅ Персонализация (что спам для вас ≠ спам для другого)
- ✅ Адаптация к новым типам спама

---

### ✅ КОГДА ИСПОЛЬЗОВАТЬ

**Идеально для:**

- ✅ Окружение **непредсказуемо** (невозможно задать правила заранее)
- ✅ Задача **слишком сложна** для программирования (распознавание образов)
- ✅ Нужна **адаптация** к изменениям (новые типы спама)
- ✅ Есть **данные** для обучения (примеры, опыт)

**Примеры задач:**

- Распознавание речи/изображений
- Игры (шахматы, го, видеоигры)
- Персонализация (рекомендации, реклама)
- Робототехника (обучение ходьбе, манипуляции)
- NLP (ChatGPT, переводчики)

---

### ❌ ОГРАНИЧЕНИЯ

**Проблема 1: Нужно много данных**

```
AlphaZero: 44 миллиона игр для обучения
ChatGPT: 300 миллиардов токенов текста
Tesla Autopilot: Миллиарды миль вождения

Без данных → плохое качество
```

**Проблема 2: Вычислительная сложность**

```
Обучение ChatGPT: $100+ миллионов (электричество, GPU)
Обучение AlphaZero: Тысячи TPU (Google)

Недоступно для маленьких проектов
```

**Проблема 3: Непредсказуемость**

```
Нейросеть = "черный ящик"
Почему ChatGPT дал ЭТОТ ответ? → Неясно
Почему Autopilot повернул? → Трудно объяснить

Проблема для критичных систем (медицина, финансы)
```

**Проблема 4: Катастрофические забывания**

```
Если обучить на новых данных → забывает старые
Пример: Переобучить ChatGPT на математике → забудет литературу
```

## 📊 СРАВНИТЕЛЬНАЯ ТАБЛИЦА 5 ТИПОВ

| Критерий         | Simple Reflex | Model-Based                | Goal-Based | Utility-Based            | Learning   |
| ---------------- | ------------- | -------------------------- | ---------- | ------------------------ | ---------- |

## 🧪 ВОПРОСЫ ДЛЯ САМОПРОВЕРКИ

### Теоретические вопросы

**1. Классификация агентов по архитектуре**

**Вопрос:** Чем принципиально отличается Simple Reflex Agent от Model-Based Reflex Agent?

<details>
<summary>💡 Подсказка</summary>

Подумайте о памяти и внутреннем представлении мира.

</details>

<details>
<summary>✅ Правильный ответ</summary>

**Simple Reflex Agent:**

- Реагирует ТОЛЬКО на текущее восприятие
- Нет памяти о прошлом
- Формула: `Действие = f(Восприятие)`

**Model-Based Reflex Agent:**

- Поддерживает внутреннюю модель мира (состояние)
- Обновляет состояние при каждом восприятии
- Формула: `Состояние = update(Состояние, Действие, Восприятие)`
- Действие зависит от состояния, а не только от текущего восприятия

**Пример:**

- Simple Reflex: Термостат (IF temp < 22°C THEN heat_on)
- Model-Based: Roomba (помнит карту помещения, куда уже ездил)

</details>

**2. Reactive vs Deliberative агенты**

**Вопрос:** Объясните концепции Reactive и Deliberative агентов. Приведите примеры каждого типа.

<details>
<summary>💡 Подсказка</summary>

Reactive — быстрая реакция на стимулы. Deliberative — обдуманное планирование.

</details>

<details>
<summary>✅ Правильный ответ</summary>

**Reactive Agents (Реактивные):**

- **Принцип:** Быстрая реакция на изменения в окружении без долгого планирования
- **Архитектура:** Прямая связь "восприятие → действие"
- **Преимущества:** Скорость реакции (миллисекунды), простота реализации
- **Недостатки:** Нет глобального планирования, может зацикливаться

**Примеры:**

- Simple Reflex Agent: датчик движения, автоматическая дверь
- Model-Based Reflex Agent: Roomba, противоугонная система

**Deliberative Agents (Обдумывающие):**

- **Принцип:** Построение плана для достижения цели через рассуждения
- **Архитектура:** Символическое представление мира + поиск решений
- **Преимущества:** Может планировать сложные последовательности, достигать долгосрочных целей
- **Недостатки:** Медленнее реагирует, требует больше вычислений

**Примеры:**

- Goal-Based Agent: GPS навигатор, шахматный AI
- Utility-Based Agent: AlphaGo, рекомендательные системы

**Hybrid Agents:**

- Комбинируют оба подхода
- Reactive слой для быстрых реакций + Deliberative слой для планирования
- Пример: Беспилотный автомобиль (быстрое торможение при опасности + планирование маршрута)

</details>

**3. Когда использовать каждый тип?**

**Вопрос:** У вас есть задача создать AI для управления складским роботом. Робот должен:

- Забирать товары с полок
- Доставлять их на станцию упаковки
- Избегать столкновений с другими роботами
- Оптимизировать время доставки

Какой тип агента вы выберете и почему? Обоснуйте свой выбор.

<details>
<summary>💡 Подсказка</summary>

Проанализируйте каждое требование: нужна ли память? планирование? оптимизация? обучение?

</details>

<details>
<summary>✅ Правильный ответ</summary>

**Рекомендация: Utility-Based Agent (или Hybrid с добавлением Learning)**

**Обоснование:**

1. **Почему НЕ Simple Reflex:**

   - Нужна память (где находятся товары, куда уже ездили)
   - Требуется планирование маршрута (не просто реакция на препятствия)

2. **Почему НЕ Model-Based Reflex:**

   - Нужно не просто "помнить состояние", а планировать путь
   - Требуется оптимизация времени (не просто достичь цели)

3. **Почему НЕ Goal-Based:**

   - Недостаточно просто "доставить товар" — нужно сделать это ОПТИМАЛЬНО
   - Множественные критерии: скорость + безопасность + энергоэффективность

4. **Почему Utility-Based:**

   - ✅ Функция полезности может балансировать критерии:
     - U(действие) = w1 × скорость - w2 × риск_столкновения - w3 × энергопотребление
   - ✅ Может планировать (через поиск действия с max utility)
   - ✅ Адаптируется к изменениям (другие роботы на складе)

5. **Опционально: + Learning Element**
   - Если склад динамичный (меняется расположение товаров)
   - Обучение на опыте: какие пути быстрее в разное время дня
   - Адаптация к поведению других роботов

**Архитектура:**

```
┌─────────────────────────────────┐
│  Восприятие (камеры, лидар)     │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  Модель мира (карта склада)     │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  Функция полезности             │
│  U = speed - risk - energy      │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  Планировщик (A* search)        │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  Действия (движение, захват)    │
└─────────────────────────────────┘
```

</details>

**4. Преимущества и недостатки типов**

**Вопрос:** Сравните Goal-Based и Utility-Based агентов. В каких ситуациях один тип явно лучше другого?

<details>
<summary>💡 Подсказка</summary>

Подумайте о ситуациях с одним критерием успеха vs множественными критериями.

</details>

<details>
<summary>✅ Правильный ответ</summary>

**Goal-Based Agent лучше, когда:**

1. **Есть четкая бинарная цель:**

   - Пример: GPS навигация ("достичь точки B")
   - Критерий успеха: Да/Нет (доехали или нет)

2. **Вычислительные ресурсы ограничены:**

   - Goal-Based проще и быстрее (не нужно оценивать utility)
   - Пример: Встроенные системы, IoT устройства

3. **Окружение детерминированно:**
   - Результат действий предсказуем
   - Пример: Сборка деталей на конвейере

**Utility-Based Agent лучше, когда:**

1. **Множественные критерии:**

   - Пример: Беспилотный автомобиль (безопасность + скорость + комфорт)
   - Нужен баланс между критериями

2. **Неопределенность:**

   - Вероятностные исходы действий
   - Пример: Финансовый трейдинг (риск vs доходность)

3. **Градации качества:**
   - "Хорошо" vs "Очень хорошо" vs "Отлично"
   - Пример: Рекомендательные системы (не просто "релевантно", а "насколько релевантно")

**Сравнительная таблица:**

| Критерий          | Goal-Based            | Utility-Based          |
| ----------------- | --------------------- | ---------------------- |
| **Цель**          | Бинарная (да/нет)     | Градуированная (0-100) |

**7. Hybrid Agents (Гибридные агенты)**

**Вопрос:** Что такое Hybrid Agent? Приведите пример системы, которая комбинирует Reactive и Deliberative подходы.

<details>
<summary>💡 Подсказка</summary>

Подумайте о ситуациях, где нужна и быстрая реакция (миллисекунды), и долгосрочное планирование (секунды/минуты).

</details>

<details>
<summary>✅ Правильный ответ</summary>

**Hybrid Agent (Гибридный агент):**

**Определение:**

- Агент, который комбинирует **Reactive** (быстрая реакция) и **Deliberative** (планирование) подходы.

**Архитектура:**

```
┌─────────────────────────────────────┐
│     HYBRID AGENT ARCHITECTURE       │
│                                     │
│  ┌───────────────────────────────┐ │
│  │   Deliberative Layer           │ │
│  │   (Planning, Goal-Based)       │ │
│  │   - Long-term planning         │ │
│  │   - Strategic decisions        │ │
│  └───────────────────────────────┘ │
│              ↓                      │
│  ┌───────────────────────────────┐ │
│  │   Reactive Layer               │ │
│  │   (Reflex Actions)             │ │
│  │   - Emergency responses        │ │
│  │   - Fast reactions             │ │
│  └───────────────────────────────┘ │
└─────────────────────────────────────┘
         ↓                 ↓
   Perception         Actions
```

**Пример 1: Беспилотный автомобиль**

**Deliberative Layer (медленный, ~секунды):**

- Планирование маршрута от А до Б (GPS навигация)
- Выбор полосы движения
- Обгон медленных машин
- Оптимизация расхода топлива

**Reactive Layer (быстрый, ~миллисекунды):**

- Экстренное торможение (пешеход на дороге)
- Уклонение от препятствия
- Удержание в полосе
- Поддержание дистанции

**Зачем оба слоя?**

- Deliberative один: Слишком медленно для экстренных ситуаций → авария
- Reactive один: Нет долгосрочного планирования → неоптимальный маршрут

**Как они взаимодействуют:**

```
Нормальная ситуация: Deliberative планирует → Reactive выполняет
Экстренная ситуация: Reactive прерывает Deliberative → быстрая реакция
После экстренности: Deliberative пересчитывает план → продолжение
```

---

**Пример 2: Промышленный робот на складе**

**Deliberative Layer:**

- Планирование маршрута к товару
- Оптимизация последовательности задач
- Координация с другими роботами

**Reactive Layer:**

- Избежание столкновений (другой робот рядом)
- Компенсация неточности захвата
- Реакция на падение товара

---

**Преимущества Hybrid:**

✅ **Robust:** Может реагировать на неожиданности
✅ **Efficient:** Оптимизирует через планирование
✅ **Safe:** Быстрые реакции в критических ситуациях
✅ **Adaptive:** Deliberative может обновлять планы

**Недостатки:**

❌ **Complexity:** Сложнее разработать и отладить
❌ **Coordination:** Нужно балансировать оба слоя
❌ **Resources:** Требует больше вычислений

**Real-world системы:**

- Tesla Autopilot, Waymo (беспилотные авто)
- Boston Dynamics роботы (Atlas, Spot)
- Дроны для доставки (Amazon Prime Air)

</details>

**Функция полезности:**

```python
def utility(action, plant, state):
    """
    action: ("water", amount) или ("no_water", 0)
    plant: {type, current_moisture, optimal_moisture, growth_rate}
    state: {weather_forecast, water_budget}
    """

    # Компоненты полезности
    growth_benefit = predict_growth(plant, action)  # 0-10
    water_cost = action.amount * water_price  # рубли
    overwater_risk = risk_of_overwatering(plant, action, state.weather)  # 0-1

    # Взвешенная сумма
    utility = (
        w1 * growth_benefit        # максимизируем рост
        - w2 * water_cost          # минимизируем расход воды
        - w3 * overwater_risk * 10 # избегаем переувлажнения
    )

    return utility

# Выбор действия
best_action = argmax(utility(action, plant, state) for action in possible_actions)
```

**Веса (обучаются со временем):**

- w1 = 5.0 (рост важнее всего)
- w2 = 1.0 (вода стоит денег)
- w3 = 3.0 (переувлажнение опасно)

```python
def utility_alert(vitals, baseline, context):
    """
    Оценивает полезность алерта
    """

    # 1. Чувствительность (насколько опасно отклонение?)
    deviation_score = 0

    # Пульс
    hr_dev = abs(vitals.hr - baseline.hr) / baseline.hr
    if hr_dev > 0.3:  # >30% отклонение
        deviation_score += 5

    # Давление
    bp_dev = abs(vitals.bp_sys - baseline.bp_sys) / baseline.bp_sys
    if bp_dev > 0.2:  # >20% отклонение
        deviation_score += 7  # давление важнее пульса

    # SpO2
    if vitals.spo2 < 90:  # критично!
        deviation_score += 10

    # 2. Тренд (ухудшается или улучшается?)
    trend_penalty = 0
    if is_improving_trend(vitals.history):
        trend_penalty = -3  # не алертить, если улучшается
    elif is_worsening_trend(vitals.history):
        deviation_score += 3  # усилить алерт

    # 3. Контекст (что происходит с пациентом?)
    context_bonus = 0
    if context.recent_surgery:  # после операции — норма колебаний
        deviation_score *= 0.7
    if context.sepsis_risk:  # сепсис — любое отклонение опасно
        deviation_score *= 1.5

    # 4. Штраф за ложные алерты (alarm fatigue)
    fp_penalty = count_recent_alerts() * 0.5

    # Итоговая полезность
    utility = deviation_score + trend_penalty + context_bonus - fp_penalty

    return utility

# Решение
if utility_alert(...) > threshold:
    send_alert(priority=calculate_priority(utility))
```

**Решение:** Не алертить немедленно, подождать подтверждения

utility = 4 - 7.5 = -3.5 < threshold

- Различные уровни приоритетов (критический, предупреждение, инфо)

✅ **Обработка edge cases:**

- Артефакты движения
- Постепенные тренды
- Баланс чувствительности

---

**Почему NOT Learning Agent?**

⚠️ **Объяснимость:**

- Врачам нужно понимать "почему алерт"
- Нейросеть = "черный ящик" → нельзя использовать в critical care

⚠️ **Регуляции:**

- FDA требует объяснимость для medical devices
- Learning agents труднее сертифицировать

⚠️ **Safety:**

- Utility-Based более предсказуем
- Learning может дать неожиданные ошибки

**Опционально:** Можно добавить Learning Element для **тонкой настройки threshold** на основе feedback врачей, но core logic должен быть Utility-Based.

</details>
