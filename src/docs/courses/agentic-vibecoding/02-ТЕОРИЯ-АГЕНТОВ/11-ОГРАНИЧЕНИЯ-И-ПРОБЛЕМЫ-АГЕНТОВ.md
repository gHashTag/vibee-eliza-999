## 2. Где AI-агенты НЕ работают: Список провалов

### ❌ Ситуация 1: Непредсказуемые обстоятельства

**Пример из практики:**

```
Задача: Организовать командировку менеджера в Париж

AI-агент:
1. ✅ Нашёл билеты
2. ✅ Забронировал отель
3. ❌ Не учёл забастовку авиадиспетчеров
4. ❌ Не предложил альтернативу
5. ❌ Забронировал отель в "плохом районе"
6. ❌ Не проверил визовые требования

Результат: Менеджер застрял в аэропорту,
потратил 3 часа на решение проблем.
```

**Почему провал?**
AI-агенты работают с **статичной информацией**. Они не понимают:

- Контекст реального мира
- Непредвиденные обстоятельства
- Человеческие нюансы (что такое "плохой район")

### ❌ Ситуация 2: Открытые проблемы без чёткого решения

**Кейс: Падение продаж в e-commerce**

```
Запрос к AI-агенту:
"Почему упали продажи на 15% за последний месяц?"

Ответ агента:
- Может быть сезонность ✓
- Возможно конкуренты снизили цены ✓
- Может быть проблема с сайтом ✓

НО:
- Не проверил реальные данные конкурентов
- Не учёл новый налог на доставку
- Не заметил баг в корзине на мобильных
- Не предложил конкретных действий
```

**Вывод:** AI-агенты хороши в **диагностике**, но плохи в **реальном анализе**.

### ❌ Ситуация 3: Обработка исключений

**Реальный случай из банка:**

Банк внедрил AI-агента для обработки заявок на кредит.

```
Стандартный случай:
- Доход > 50,000
- Кредитный рейтинг > 700
- Стаж > 1 год
Решение: ✅ Одобрено

Исключение:
- Доход = 45,000
- Кредитный рейтинг = 650
- НО: Клиент — основатель стартапа с $2M инвестиций
- НО: Есть недвижимость на $500K
Решение AI: ❌ Отклонено

Человек: ✅ Одобрил (с учётом контекста)
```

**Проблема:** AI не понимает **контекст** и **исключения из правил**.

### ❌ Ситуация 4: Адаптация к изменяющимся условиям

**Пример: Маркетинговая кампания**

```
AI-агент запустил рекламу:
- День 1-3: CTR 2.5% ✅
- День 4: CTR упал до 0.5% ❌

Человек:
- Заметил, что конкурент запустил акцию
- Изменил креативы
- Скорректировал ставки

AI-агент:
- Продолжал показывать ту же рекламу
- Сжёг бюджет впустую
- Не предложил изменений
```

### 📋 Чек-лист: Когда НЕ использовать AI-агентов

- [ ] Задача требует здравого смысла
- [ ] Нужно учитывать непредсказуемые обстоятельства
- [ ] Требуется понимание человеческих эмоций
- [ ] Необходимо принимать решения в условиях неопределённости
- [ ] Задача критична для безопасности/финансов
- [ ] Нужна креативность вне шаблонов
- [ ] Требуется адаптация к быстро меняющейся ситуации

## 3. Почему агенты fail: Фундаментальные причины

### 🧠 Причина 1: Ограниченное понимание контекста

**Аналогия с иностранцем:**

Представьте иностранца, который выучил русский язык по учебникам:

```
Фраза: "Руки не доходят до этого"

Иностранец понимает:
"У человека проблемы с анатомией рук"

Реальное значение:
"Нет времени на эту задачу"
```

**Так же работает AI-агент:**

```
Запрос: "Найди лучший ресторан для свидания"

AI понимает:
- "Лучший" = высокий рейтинг
- "Ресторан" = место, где готовят еду
- "Свидание" = встреча двух людей

AI НЕ понимает:
- Романтическую атмосферу
- Не слишком шумно для разговора
- Не слишком дорого (чтобы не выглядеть понтово)
- Не слишком дёшево (чтобы не выглядеть скупо)
```

**Результат:** AI выберет Michelin-ресторан за $500 на персону или McDonald's.

### 🤷 Причина 2: Отсутствие здравого смысла

**Кейс: AI-ассистент для планирования**

```
Задача: Запланировать встречу с клиентом

AI-предложение:
"Встреча назначена на 25 декабря в 9:00"

Проблема:
- 25 декабря = Рождество
- Офисы закрыты
- Люди с семьями

Здравый смысл (человек):
"Это праздник, перенесём на 26-е"

AI-агент:
"В календаре есть свободное время"
```

**Почему так происходит?**

AI-агенты обучены на **паттернах**, а не на **понимании мира**.

```
Паттерн: "Если календарь свободен → назначить встречу"
Здравый смысл: "Если праздник → НЕ назначать"
```

### 🔄 Причина 3: Неспособность переносить знания

**Проблема transfer learning:**

```
Домен A: Продажи автомобилей
AI-агент обучен:
- Квалифицировать лиды
- Понимать возражения
- Закрывать сделки

Домен B: Продажи программного обеспечения
AI-агент:
❌ Не может применить знания из домена A
❌ Нужна полная переобучение
❌ Не понимает, что принципы продаж схожи
```

**Аналогия:** Представьте повара, который умеет готовить только итальянскую кухню. Если попросите приготовить китайское блюдо, он не сможет **даже с рецептом** — потому что не понимает **принципы** готовки, только **конкретные рецепты**.

### 🌫️ Причина 4: Борьба с неопределённостью

**Пример: Анализ рынка**

```
Вопрос: "Стоит ли запускать новый продукт?"

Человек-аналитик:
- Анализирует 20 факторов
- Делает предположения на основе опыта
- Оценивает риски
- Выводы: "Да, но с осторожностью, потому что..."

AI-агент:
- Анализирует 100 факторов
- НЕ может делать предположения
- НЕ понимает связь факторов
- Выводы: "Недостаточно данных для ответа"
```

**Проблема:** AI требует **полные данные**, жизнь даёт **неполные**.

### 🌍 Причина 5: Отсутствие модели мира

**Что такое "модель мира"?**

Это понимание того, **как устроен мир** на фундаментальном уровне.

**Пример: Физика**

```
Человек:
"Если я уроню чашку, она разобьётся"
Почему? Понимание гравитации, хрупкости материалов

AI-агент:
"Статистически, в 87% случаев чашки разбиваются при падении"
Почему? Потому что так было в данных
```

**Почему это важно?**

```
Задача: "Установи этот шкаф в комнате"

Человек:
1. Оценивает размер дверного проёма
2. Понимает, что шкаф не пройдёт
3. Разбирает шкаф
4. Заносит по частям
5. Собирает внутри

AI-агент:
1. Команда "установить"
2. ??? (как занести)
3. Fail
```

## 4. Технические ограничения: Железо и софт

### 📏 Проблема 1: Ограничения контекстного окна

**Что это такое простыми словами:**

Представьте, что AI-агент — это человек с очень плохой памятью:

```
Контекстное окно = 200,000 токенов
≈ 150,000 слов
≈ 300 страниц текста

Звучит много? НЕТ.
```

**Реальный кейс:**

```
Задача: "Проанализируй все документы проекта"

Документы проекта:
- Техническая спецификация: 50 страниц
- Бизнес-требования: 30 страниц
- История изменений: 100 страниц
- Код: 5,000 строк
- Тесты: 2,000 строк
- Документация API: 80 страниц

Итого: ~400-500 страниц

AI-агент:
❌ Не помещается в контекст
❌ Нужно разбивать на части
❌ Теряется связь между частями
❌ Неполный анализ
```

**Что происходит при превышении лимита:**

```
Страница 1-300: ✅ Помнит
Страница 301: ⚠️ Начинает забывать страницу 1
Страница 350: ❌ Забыл половину документа
```

**Аналогия:** Это как читать 500-страничную книгу, но помнить только последние 300 страниц.

### ⏱️ Проблема 2: Проблемы с задержкой (медленное мышление)

**Сравнение скорости:**

| Задача                     | Человек      | AI-агент (GPT-4) |
| -------------------------- | ------------ | ---------------- |
| Простой ответ              | 2-5 сек      | 3-10 сек         |
| Анализ документа           | 5-10 мин     | 2-5 мин          |
| Написание кода             | 30-60 мин    | 10-30 мин        |
| **Цепочка из 10 действий** | **1-2 часа** | **10-20 часов**  |

**Почему цепочка так долго?**

```
Действие 1: Анализ задачи (5 мин)
  ↓
Действие 2: Поиск информации (10 мин)
  ↓
Действие 3: Генерация решения (15 мин)
  ↓
... (ещё 7 действий)
  ↓
Итого: 150+ минут

При этом:
- Каждое действие ждёт завершения предыдущего
- Нет параллелизма
- API rate limits
- Сетевые задержки
```

**Реальный кейс:**

```
Компания внедрила AI-агента для обработки заявок:

День 1:
"Супер! Агент обрабатывает заявки!"

День 7:
"Почему заявка обрабатывается 2 часа?"
"Раньше менеджер делал это за 15 минут"

Причина:
- AI делает 20 API вызовов
- Каждый вызов = 1-2 минуты
- Итого: 40 минут только на API
- + обработка, + анализ = 2 часа
```

### 🧠 Проблема 3: Ограничения памяти

**Типы памяти AI-агента:**

```
┌─────────────────────────────────────┐
│ КРАТКОСРОЧНАЯ ПАМЯТЬ                │
│ (Context Window)                    │
│ Время жизни: 1 сессия               │
│ Объём: ~300 страниц                 │
└─────────────────────────────────────┘
         ↓ (забывается)
┌─────────────────────────────────────┐
│ ДОЛГОСРОЧНАЯ ПАМЯТЬ                 │
│ (Векторные базы, RAG)               │
│ Время жизни: вечно                  │
│ Проблема: неточный поиск            │
└─────────────────────────────────────┘
```

**Проблема: Разрыв между краткосрочной и долгосрочной памятью**

```
Сценарий: AI-агент для поддержки клиентов

Клиент пишет:
"Неделю назад вы обещали вернуть деньги"

AI-агент:
1. Ищет в векторной базе
2. Находит 5 похожих диалогов
3. НО не тот, что нужен
4. Ответ: "Я не нашёл информацию об этом обещании"

Клиент: 😡 "Я разговаривал с вами 7 дней назад!"

Проблема:
- Краткосрочная память уже забыла
- Долгосрочная память не точна
- Нет "средней" памяти
```

### 🎭 Проблема 4: Галлюцинации (выдумывание фактов)

**Что такое галлюцинации в AI?**

Это когда AI **уверенно** говорит **полную чушь**.

**Примеры из практики:**

```
Запрос: "Кто выиграл Нобелевскую премию по физике в 2023?"

AI-агент:
"Нобелевскую премию по физике в 2023 году получил
Джон Смит за исследования квантовой гравитации"

Реальность:
❌ Джон Смит — выдуманное имя
❌ Квантовая гравитация — не была темой премии
❌ Реальные лауреаты: совсем другие люди
```

**Почему AI галлюцинирует?**

```
AI обучен на паттернах:

Паттерн:
"Нобелевская премия по физике в [год] получил [имя] за [достижение]"

Если не знает ответа:
1. ❌ Не говорит "я не знаю"
2. ✅ Генерирует правдоподобный ответ
3. ❌ Уверенно врёт
```

**Статистика галлюцинаций:**

| Область                  | Частота галлюцинаций |
| ------------------------ | -------------------- |
| Факты и даты             | 15-30%               |
| Технические спецификации | 20-40%               |
| Финансовые данные        | 10-25%               |
| Медицинская информация   | 25-50%               |

**Реальный ущерб от галлюцинаций:**

```
Кейс: Юридическая фирма использовала AI для подготовки документов

Результат:
- AI "придумал" несуществующие судебные прецеденты
- Юристы не проверили
- Документы поданы в суд
- Суд обнаружил фальсификацию
- Фирма оштрафована на $10,000
- Репутация разрушена
```

## 5. Экономические ограничения: Дорого и невыгодно

### 💰 Стоимость: $300+ на одну сложную задачу

**Разбор реальной стоимости:**

```
Задача: "Разработай стратегию маркетинга для нового продукта"

Стоимость AI-агента:
─────────────────────────────────────────
Анализ рынка:
- 50,000 токенов на вход
- 20,000 токенов на выход
- Стоимость (GPT-4): $1.50

Генерация идей:
- 30,000 токенов на вход
- 40,000 токенов на выход
- Стоимость: $2.10

Детализация стратегии:
- 100,000 токенов на вход
- 50,000 токенов на выход
- Стоимость: $4.50

Итерации и правки (x5):
- Каждая итерация: $1.50
- Итого: $7.50

ИТОГО: $15.60 за базовую работу
─────────────────────────────────────────

НО это только начало:

Дополнительные вызовы:
- Поиск данных: $5
- Проверка фактов: $3
- Генерация визуализаций: $10
- Форматирование: $2

РЕАЛЬНАЯ стоимость: $35-40 за одну задачу
```

**Сравнение с человеком:**

```
Маркетолог (junior):
- Ставка: $25/час
- Время: 4 часа
- Стоимость: $100

Но:
✅ Понимает контекст
✅ Задаёт уточняющие вопросы
✅ Учитывает нюансы
✅ Не галлюцинирует

AI-агент:
- Стоимость: $40
- Время: 2 часа

Но:
❌ Нужна проверка ($50 человеческого времени)
❌ Переделки ($20 дополнительно)
❌ Галлюцинации (риск $1000+ ошибок)

ИТОГО: $110+ и выше риски
```

**Когда AI экономически выгоден:**

| Задача                       | AI выгоден? | Почему?                    |
| ---------------------------- | ----------- | -------------------------- |
| Массовая генерация контента  | ✅ Да       | Объём x скорость           |
| Анализ больших данных        | ✅ Да       | Человек физически не может |
| Простые повторяющиеся задачи | ✅ Да       | Автоматизация окупается    |
| Сложные творческие задачи    | ❌ Нет      | Нужна переделка            |
| Критические решения          | ❌ Нет      | Риски > экономии           |

### ⏱️ API Rate Limits: Вы не можете работать быстро

**Что такое rate limits простыми словами:**

Это ограничение на **количество запросов** к AI в единицу времени.

```
Типичные лимиты OpenAI:

GPT-4:
- 10,000 запросов в день
- 40,000 токенов в минуту
- 200 запросов в минуту

Звучит много? Посчитаем:
```

**Реальный кейс: Обработка заявок**

```
Компания получает 1,000 заявок в час пик

Одна заявка требует:
- Анализ: 1 запрос
```

### 🔧 Стратегия 4: Механизмы отката (Fallback)

**Принцип: Всегда иметь план B**

```
Основной план → AI обрабатывает запрос
       │
       │ (если AI fail)
       ↓
Fallback 1 → Попытка с упрощённым промптом
       │
       │ (если снова fail)
       ↓
Fallback 2 → Передача человеку
       │
       │ (если человек недоступен)
       ↓
Fallback 3 → Стандартный ответ + уведомление
```

**Пример: Служба поддержки**

```javascript
// Псевдокод системы с Fallback

function handleCustomerQuery(query) {
  // Попытка 1: AI обработка
  try {
    const aiResponse = AI.process(query);
    if (aiResponse.confidence > 0.8) {
      return aiResponse;
    }
  } catch (error) {
    log("AI failed, trying fallback");
  }

  // Fallback 1: Поиск в базе знаний
  try {
    const kbResponse = KnowledgeBase.search(query);
    if (kbResponse.found) {
      return kbResponse;
    }
  } catch (error) {
    log("KB search failed");
  }

  // Fallback 2: Передача человеку
  try {
    return HumanAgent.assign(query);
  } catch (error) {
    log("No human agents available");
  }

  // Fallback 3: Стандартный ответ
  return {
    message:
      "Извините, сейчас мы не можем ответить на ваш вопрос. " +
```

## 🧠 ТЕОРЕТИЧЕСКАЯ ЧАСТЬ: Фундаментальные ограничения AI-агентов

### 1. Теоретические границы интеллекта агентов

**Философская проблема: "Китайская комната" Сёрла**

```
┌──────────────────────────────────────────────┐
│ ЧЕЛОВЕК В КОМНАТЕ                            │
│                                              │
│ Не знает китайского языка                   │
│ Получает: Китайские символы (вход)          │
│ Использует: Книгу правил                     │
│ Выдаёт: Китайские символы (выход)           │
│                                              │
│ Вопрос: Понимает ли человек китайский?      │
│ Ответ: НЕТ. Он следует правилам.            │
└──────────────────────────────────────────────┘

То же с AI-агентами:
- Они следуют паттернам (правилам)
- Но НЕ ПОНИМАЮТ смысл
- Это фундаментальное ограничение
```

**Проблема символьного заземления (Symbol Grounding Problem)**

```
Человек:
"Яблоко" → Видел, трогал, ел → Понимает концепцию

AI-агент:
"Яблоко" → Набор токенов → Статистическая связь с другими токенами
           НЕТ реального опыта → НЕТ понимания
```

**Следствия для практики:**

- AI не может обобщать за пределы обучающих данных
- Нет "здравого смысла" — только паттерн-матчинг
- Креативность ограничена комбинацией известного
- Невозможно истинное понимание намерений пользователя

### 2. Проблема масштабирования: Почему "больше" ≠ "лучше"

**Закон убывающей отдачи в AI:**

```
┌─────────────────────────────────────────┐
│ РОСТ МОДЕЛИ vs РОСТ СПОСОБНОСТЕЙ        │
│                                         │
│ Параметры модели:                       │
│ 1B   → 70% accuracy                     │
│ 10B  → 80% accuracy  (+10%)             │
│ 100B → 85% accuracy  (+5%)              │
│ 1T   → 87% accuracy  (+2%)              │
│                                         │
│ Стоимость обучения:                     │
│ 1B   → $10K                             │
│ 10B  → $100K   (10x)                    │
│ 100B → $1M     (10x)                    │
│ 1T   → $10M    (10x)                    │
│                                         │
│ Вывод: Каждый 10x рост стоимости        │
│ даёт всё меньший прирост точности       │
└─────────────────────────────────────────┘
```

**Проблемы масштабирования агентных систем:**

```
1 агент:
✅ Быстрая координация
✅ Простая отладка
✅ Предсказуемое поведение

10 агентов:
⚠️  Координация сложнее
⚠️  Больше точек отказа
⚠️  Emergent behaviour (неожиданное поведение)

100 агентов:
❌ Coordination overhead > productivity gains
❌ Непредсказуемые взаимодействия
❌ Debugging nightmare
❌ Стоимость коммуникации > стоимости работы
```

**Математическая модель координационных затрат:**

```
Coordination Cost = O(n²)
где n = количество агентов

Пример:
2 агента:  4 возможных взаимодействия
5 агентов: 25 возможных взаимодействий
10 агентов: 100 возможных взаимодействий
50 агентов: 2,500 взаимодействий

При n > 20: Coordination Cost > Productivity Gain
```

### 3. Hallucinations & Reliability: Статистическая неизбежность

**Теория информации: Энтропия в генерации**

```
AI генерирует текст как:
P(word_n | word_1, word_2, ..., word_n-1)

Проблема:
- Каждое слово — вероятностный выбор
- Нет "истинности" в модели
- Только "правдоподобность"

Результат:
Чем длиннее генерация, тем выше вероятность ошибки

Математика:
P(все слова верны) = P(w1) × P(w2) × ... × P(wn)

Если P(каждое слово верно) = 0.99:
- Предложение (10 слов): 90% верно
- Параграф (100 слов): 37% верно
- Статья (1000 слов): 0.004% верно (практически гарантированы ошибки)
```

**Типология галлюцинаций по происхождению:**

```
1. СТАТИСТИЧЕСКИЕ ГАЛЛЮЦИНАЦИИ
   Причина: Модель экстраполирует паттерны
   Пример: "В 2024 году население Земли 12 млрд"
            (просто продолжает тренд роста)

2. КОНФАБУЛЯЦИИ (ЗАПОЛНЕНИЕ ПРОБЕЛОВ)
   Причина: Модель не может сказать "не знаю"
   Пример: Запрос: "Кто был президентом Антарктиды в 1950?"
            AI: "Джон Смит был президентом..." (выдумка)

3. КОНТЕКСТНЫЕ ГАЛЛЮЦИНАЦИИ
   Причина: Потеря контекста в длинной генерации
   Пример: Начало: "Кошка чёрная"
            Через 200 слов: "Эта белая кошка..."

4. ГАЛЛЮЦИНАЦИИ ИСТОЧНИКОВ
   Причина: Смешивание разных источников
   Пример: "Согласно исследованию MIT (2024)..."
            (исследования не существует)
```

**Фундаментальная невозможность 100% надёжности:**

```
ДОКАЗАТЕЛЬСТВО от противного:

Предположим, AI-агент 100% надёжен.

Тогда:
1. Он всегда даёт правильный ответ
2. Даже при недостатке данных
3. Даже при противоречивых данных

НО:
Theorem (Gödel's Incompleteness):
В любой достаточно сложной системе
существуют утверждения, которые:
- Истинны, но недоказуемы
- ИЛИ невозможно определить истинность

Следствие:
AI-агент либо:
а) Откажется отвечать (не 100% полезности)
б) Даст ответ (не 100% надёжности)

∴ 100% надёжность невозможна теоретически
```

**Количественные критерии:**

```

   > 1,000 однотипных операций в месяц

2. Структурированность:
   > 80% задач имеют схожую структуру

3. Стоимость ошибки:
   < $100 за одну ошибку

4. Доступность данных:
   > 10,000 примеров для обучения/настройки

5. Временные рамки решения:
   > 5 минут на задачу (есть время на проверку AI)

НЕ ИСПОЛЬЗУЙТЕ AI, если:

1. Критичность:
   Ошибка может стоить > $10,000 или жизни

2. Юридическая ответственность:
   Требуется личная подпись/ответственность

3. Креативность:
   Нужно "out of the box" мышление

4. Контекст:
   > 50% решения зависит от неявного контекста

5. Этика:
   Решение затрагивает права/свободы людей
```

**Таксономия задач по пригодности для AI:**

```
КАТЕГОРИЯ A: ИДЕАЛЬНО ДЛЯ AI (90%+ успешности)
─────────────────────────────────────────────
• Ввод данных (data entry)

КАТЕГОРИЯ B: ХОРОШО ДЛЯ AI (70-90% успешности)
─────────────────────────────────────────────
• Генерация контента (с редактурой)

• Анализ данных (с проверкой)
• Резюмирование текстов
• Поиск информации

КАТЕГОРИЯ C: СОМНИТЕЛЬНО (40-70% успешности)
─────────────────────────────────────────────
• Сложный анализ рынка
• Креативная генерация идей
• Планирование проектов
• Написание кода (сложного)
• Медицинская диагностика

КАТЕГОРИЯ D: НЕ РЕКОМЕНДУЕТСЯ (0-40% успешности)
─────────────────────────────────────────────
• Юридические заключения
• Финансовые решения высокого риска
• Стратегическое планирование
• Оценка этических дилемм
• Критические системы безопасности
```

**Теорема о пригодности задач:**

```
Задача пригодна для AI-агента тогда и только тогда, когда:

1. ∃ формальная спецификация задачи
   (можно описать правилами)

2. ∃ метрика оценки результата
   (можно объективно измерить качество)

3. Стоимость (ошибки) < Выгода (автоматизации)
   (экономически оправдано)

4. ∃ механизм коррекции
   (ошибки можно исправить)

Если хотя бы одно условие НЕ выполнено →
задача НЕ подходит для AI-агента
```

### Часть 2: Mitigation Controls (20 минут)

Для каждого риска с Severity ≥ 7 разработайте:

```markdown
### РИСК R1: AI одобрит мошенническую заявку

**Preventive Controls (до события):**

1. Multi-agent verification (3 агента голосуют)
2. Rule-based hard limits (сумма > $50K → только human)
3. Continuous monitoring (real-time fraud score)

**Detective Controls (обнаружение):**

1. Pattern analysis (аномалии в одобренных заявках)
2. Random sampling (10% проверка человеком)
3. Customer complaints tracking

**Corrective Controls (после события):**

1. Instant loan freeze mechanism
2. Automated notification to fraud team
3. Root cause analysis within 24h

**Compensating Controls (если основные fail):**

1. Insurance coverage (до $500K)

- Current baseline: 0.5%
- Alert threshold: > 0.2%
```

### Часть 3: Testing & Validation Plan (15 минут)

```markdown
## Фаза 1: Sandbox Testing (Месяц 1-2)

- [ ] Synthetic data testing (100K cases)
- [ ] Red team testing (adversarial attacks)
- [ ] Edge case library (500 known failures)
- Success criteria: 99% accuracy on known cases

## Фаза 2: Shadow Mode (Месяц 3-4)

- [ ] AI runs parallel to humans (не принимает решения)
- [ ] Comparison: AI vs Human decisions
- [ ] Measure: false positive/negative rates
- Success criteria: AI ≥ 95% human performance

## Фаза 3: Limited Rollout (Месяц 5-6)

- [ ] 5% of real traffic
- [ ] Human-in-the-loop for ALL decisions
- [ ] Daily review meetings
- Success criteria: 0 critical errors in 2 months

## Фаза 4: Gradual Scale (Месяц 7-12)

- [ ] 5% → 20% → 50% → 80% traffic
- [ ] Reduce human oversight gradually
- [ ] Weekly performance reviews
- Success criteria: ROI > 0, errors < baseline
```

### Часть 4: Kill Switch & Rollback Strategy (10 минут)

```markdown
## Автоматические триггеры отключения:

1. **Instant Kill (немедленное отключение):**

   - Error rate > 5% в течение 1 часа
   - Регуляторное нарушение обнаружено
   - Security breach detected
   - Финансовые потери > $10K/час

2. **Gradual Rollback (постепенное):**

   - Accuracy падает ниже 90%
   - Customer complaints spike > 2x baseline
   - Latency > 10 seconds

3. **Manual Override:**
   - CEO/CTO могут отключить в 1 клик
   - Доступно 24/7 on-call team

## Rollback Plan:

Уровень 1 (5 минут):

- Stop new requests to AI
- Route all to human queue
- Freeze current AI decisions (manual review)

Уровень 2 (30 минут):

- Revert to last stable version
- Full audit of decisions in last 24h

Уровень 3 (24 часа):

- Complete system shutdown
- Forensic analysis
- Customer notifications
```

**Формат сдачи:**

Полный документ в Markdown (3-5 страниц) с:

- Risk matrix (таблица)
- Top-5 рисков с детальными controls
- Testing plan с timeline
- Kill switch protocol

**Критерии оценки:**

- Полнота рисков (25%)

- Практичность testing plan (25%)
