## 💬 Как общаться с Claude

### **Принципы эффективного общения**

**1. Будьте конкретны**

❌ **Плохо:** "Сделай что-нибудь с ботом"

✅ **Хорошо:** "Добавь в бота команду /help которая показывает список команд"

**2. Описывайте контекст**

❌ **Плохо:** "Исправь ошибку"

**3. Разбивайте большие задачи**

❌ **Плохо:** "Создай полностью готовый интернет-магазин"

```

2. "Добавь модель Product с полями: name, price, description"
3. "Создай API эндпоинт для получения списка товаров"
```

**4. Используйте естественный язык**

✅ Говорите как с коллегой, а не как с роботом:

- "Можешь помочь оптимизировать этот запрос к БД?"
- "Мне кажется здесь есть утечка памяти, посмотри пожалуйста"
- "Добавь комментарии к этой функции, она сложная"

## 🔄 Checkpoint система

Claude Code автоматически сохраняет состояние перед каждым изменением.

### **Автоматические checkpoint'ы**

```
> Добавь валидацию email в функцию register

✓ Checkpoint created: before editing src/auth.js
✓ File modified: src/auth.js
✓ Changes applied successfully
```

### **Откат изменений**

**Метод 1: Нажать ESC ESC**

```
> Добавь новую функцию...
[Claude делает изменения]

# Передумали? Нажмите ESC два раза
ESC ESC

✓ Reverted to previous checkpoint
✓ Changes undone: src/auth.js
```

**Метод 2: Команда /rewind**

```
> /rewind

Available checkpoints:
1. Before editing src/auth.js (5 min ago)
2. Before creating src/utils.js (15 min ago)
3. Before deleting old-code.js (30 min ago)

Select checkpoint to restore [1-3]: 2

✓ Restored to checkpoint: Before creating src/utils.js
```

### **Просмотр checkpoint'ов**

```bash
> /checkpoints

📋 Recent Checkpoints:
┌────┬──────────────────────┬─────────────┬──────────────────┐
│ ID │ Description          │ Time        │ Files Changed    │
├────┼──────────────────────┼─────────────┼──────────────────┤
│ 1  │ Before editing auth  │ 5 min ago   │ src/auth.js      │
│ 2  │ Before creating util │ 15 min ago  │ src/utils.js     │
│ 3  │ Before git commit    │ 30 min ago  │ 5 files          │
└────┴──────────────────────┴─────────────┴──────────────────┘
```

`★ Insight ─────────────────────────────────────`
**Безопасность через checkpoint'ы**: Система checkpoint'ов в Claude Code реализует философию "экспериментируй без страха". Вы можете пробовать смелые решения, зная что всегда можно вернуться назад. Это как сохранения в видеоиграх — смерть не страшна, когда есть save point.

## 💡 Best Practices

### **1. Используйте checkpoint'ы осознанно**

```bash
# Создайте checkpoint перед рискованными изменениями
> /checkpoint "Before major refactoring"

# Экспериментируйте свободно
> Попробуй переписать это на функциональный стиль

# Не понравилось? Откатывайтесь
> ESC ESC
```

### **2. Очищайте контекст когда нужно**

```bash
# После завершения большой задачи
> /clear

# При переключении между модулями
> /focus src/api/
```

### **3. Сохраняйте промежуточные результаты**

```bash
# После значимых изменений делайте коммит
> Сделай git commit с описанием изменений

# Checkpoint автоматический, но коммит — явное сохранение
```

### **4. Разбивайте сложные задачи**

```bash
# Вместо одного большого запроса
❌ "Создай полный бэкенд с авторизацией и платежами"

# Делайте пошагово
✅ "Создай структуру Express проекта"
✅ "Добавь JWT авторизацию"
✅ "Интегрируй Stripe для платежей"
```

### **Тест 1: Основы интерактивного режима**

**Вопрос 1:** Что произойдёт если в интерактивном режиме нажать ESC ESC?

<details>
<summary>Показать ответ</summary>

**Ответ:** Будет выполнен откат к предыдущему checkpoint'у (rewind). Claude Code автоматически сохраняет состояние перед каждым изменением, и ESC ESC возвращает проект к состоянию до последнего изменения.

**Вопрос 2:** Какая разница между командами `/clear` и `/exit`?

<details>
<summary>Показать ответ</summary>

**Ответ:**

- `/clear` — очищает контекст разговора (Claude "забывает" предыдущий диалог), но остаётся в интерактивной сессии. Полезно при переключении между разными задачами.
- `/exit` — полностью завершает интерактивную сессию Claude Code и возвращает в обычный терминал. То же самое делает `Ctrl+D`.

</details>

### **Тест 3: Best Practices**

**Вопрос 8:** Почему важно делать git commit после значимых изменений, если есть checkpoint система?

<details>
<summary>Показать ответ</summary>

**Ответ:**

**Checkpoint'ы — временные:**

- Хранятся только в текущей сессии Claude Code
- Автоматически создаются перед изменениями
- Могут быть перезаписаны новыми checkpoint'ами
- НЕ сохраняются между запусками Claude

**Git commit — постоянное сохранение:**

- Сохраняется в истории проекта навсегда
- Доступен в любое время (не только в Claude)
- Синхронизируется с удалённым репозиторием
- Содержит описание изменений

**Правило:** Checkpoint для экспериментов, git commit для готовых решений.

```bash
# Workflow
1. Эксперимент → автоматический checkpoint
2. Понравилось → git commit
3. Не понравилось → ESC ESC (rewind)
```

</details>

**Вопрос 10:** В каких случаях стоит использовать команду `/clear`?

<details>
<summary>Показать ответ</summary>

**Ответ:**

**Используйте `/clear` когда:**

1. **Переключаетесь на другую задачу:**

   ```
   > Закончил работу с авторизацией
   > /clear
   > Теперь буду работать с платёжной системой
   ```

2. **Контекст переполнен:**

   ```
   # После долгого диалога Claude может "забыть" начало
   > /clear
   # Начинаете с чистого листа
   ```

3. **Claude даёт неожиданные ответы:**

   ```
   # Если Claude предлагает решения не в тему
   > /clear
   # Переформулируйте задачу заново
   ```

4. **После завершения большого рефакторинга:**
   ```
   > Рефакторинг завершён, сделан git commit
   > /clear
   # Готовы к новой задаче
   ```

**НЕ используйте `/clear`:**

- В середине сложной задачи (потеряете контекст)
- Если нужно сослаться на предыдущий диалог

</details>

Создайте 4 панели:

### **Уровень 3: Проектное (50-60+ минут)**

**Тема:** Создание персонального CLI workflow с алиасами и автоматизацией

**Задание:**
Создайте персональную систему для максимально эффективной работы с Claude Code.

**Шаг 1: Анализ текущего workflow (10 мин)**
Ответьте на вопросы:

1. Какие команды Claude Code вы используете чаще всего?

3. Сколько времени тратите на переключение между инструментами?
4. Какие ручные операции можно автоматизировать?

**Шаг 2: Создание custom shortcuts (15 мин)**

Создайте файл `~/.claude-aliases` со своими командами:

```bash
# ~/.claude-aliases

# Быстрый запуск Claude в проекте
alias c='claude'
alias ci='claude --interactive'
alias cq='claude'  # quick question

# Работа с checkpoint'ами
alias crw='claude /rewind'
alias cck='claude /checkpoints'

# Комплексные workflow
alias cdev='tmux new -s dev -d "claude" \; split-window -h "npm run dev" \; split-window -v "npm test -- --watch"'

# Быстрые вопросы
alias cfix='claude "Проанализируй последний git diff и найди потенциальные проблемы"'
alias ctest='claude "Создай тесты для последнего изменённого файла"'
alias cdoc='claude "Добавь JSDoc комментарии к функциям в последнем изменённом файле"'

# Git + Claude интеграция
alias cgc='claude "Проанализируй git diff и предложи commit message" && git add . && git commit'
```

Добавьте в `~/.zshrc` или `~/.bashrc`:

```bash
[ -f ~/.claude-aliases ] && source ~/.claude-aliases
```

**Шаг 3: Автоматизация с tmuxinator (15 мин)**

Установите tmuxinator:

```bash
gem install tmuxinator
```

Создайте конфиг `~/.config/tmuxinator/claude.yml`:

```yaml
name: claude-workspace
root: ~/projects/<your-project>

windows:
  - main:
      layout: main-vertical
      panes:
        - claude
        - npm run dev
  - code:
      layout: tiled
      panes:
        - vim # или code .
        - git status
  - tests:
      - npm test -- --watch
  - logs:
      - tail -f app.log
```

Запуск: `tmuxinator start claude-workspace`

**Шаг 4: Pre-commit hooks с Claude (10 мин)**

Создайте `.git/hooks/pre-commit`:

```bash
#!/bin/bash

echo "🤖 Claude Code проверяет изменения..."

# Попросить Claude проверить код перед коммитом
claude "Проанализируй git diff --staged и найди:
1. Потенциальные баги
2. Проблемы с производительностью
3. Нарушения best practices
4. Закомментированный код

Если всё ок — выведи ✅ PASSED
Если есть проблемы — выведи ❌ и список проблем"

# Если Claude нашёл проблемы — спросить подтверждение
read -p "Продолжить коммит? (y/n) " -n 1 -r
echo
if [[ ! $REPLY =~ ^[Yy]$ ]]; then
    exit 1
fi
```
