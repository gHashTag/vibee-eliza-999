# 05. Slash команды - Ваши суперспособности

> _"Команда - это не просто сокращение. Это магическое заклинание, которое превращает намерение в действие."_

## Подводка: От диалога к автоматизации

В предыдущей статье мы научились работать с файлами через диалог с Claude. Теперь представьте: вы часто делаете одни и те же операции. Каждый раз объяснять заново? Нет, вы создаёте **slash команды** - свои персональные инструменты.

Slash команды - это как макросы в Excel или алиасы в терминале, только намного мощнее. Это **ваши собственные функции Claude**, настроенные под вашу манеру работы.

## Что такое slash команды?

### Базовая концепция

Slash команда - это файл с инструкциями для Claude, который вы можете вызвать одной строкой.

**Без команды:**

```
Сгенерируй сценарий для Instagram Reels на тему нейросетей:
1. Вирусный хук
2. 3 боли аудитории
3. 3 преимущества решения
4. Призыв к действию
5. Формат: 30 секунд
6. Стиль: Дерзкий и энергичный
```

**С командой:**

```
/scenario "нейросети"
```

Одна строка вместо семи. Экономия времени в 10 раз.

### Философия команд

**Инсайт:** Slash команды - это не автоматизация рутины. Это **кристаллизация вашего опыта** в переиспользуемые инструменты.

Каждая команда - это ваш способ думать и работать, упакованный в формат, который понимает Claude.

## Встроенные команды Claude Code

### /help - Справочник возможностей

```
/help
```

Показывает:

- Список всех доступных команд
- Описание каждой команды
- Примеры использования
- Горячие клавиши

**Когда использовать:**

- Забыли название команды
- Изучаете новые возможности
- Нужна подсказка по синтаксису

### /clear - Очистка контекста

```
/clear
```

Очищает историю диалога и освобождает контекст.

**Важно:** Используйте когда:

- Переключаетесь на новую задачу
- Контекст перегружен старой информацией
- Хотите начать "с чистого листа"

**Инсайт:** Контекст в Claude - как оперативная память. Иногда нужна "перезагрузка" для эффективной работы.

### /review - Проверка кода

```
/review
```

Claude анализирует последние изменения:

- Потенциальные баги
- Проблемы безопасности
- Улучшения производительности
- Соответствие best practices

**Пример использования:**

```
[Вы внесли изменения в код]
/review
```

Claude:

```
✅ Изменения выглядят хорошо
⚠️ Рекомендую добавить обработку ошибок в строке 45
🔒 Используйте environment variables для API ключей
```

### /exit - Выход

```
/exit
```

Корректно завершает сессию, сохраняя все изменения.

## Создание собственных команд

### Структура команды

Все команды хранятся в папке `.claude/commands/`

**Базовая структура файла:**

```markdown
---
name: command-name
description: Когда использовать эту команду
argument-hint: [аргумент1] [--флаг] 

---

Инструкции для Claude что делать при вызове команды.

Можно использовать переменные:

- $ARGUMENTS - все аргументы
- $1 - первый аргумент
- $2 - второй аргумент
- $3 - третий аргумент
```

### Пример 1: Простая команда без аргументов

**Файл:** `.claude/commands/check-project/index.js`

```markdown
---
name: check-project
description: Проверка здоровья проекта
---

Проверь текущий проект на:

1. Отсутствующие зависимости
2. Устаревшие пакеты
3. Проблемы безопасности
4. Неиспользуемый код
5. Дублирование логики

Выдай структурированный отчёт с приоритетами.
```

**Использование:**

```
/check-project
```

### Пример 2: Команда с аргументами

**Файл:** `.claude/commands/component/index.js`

```markdown
---
name: component
description: Создать React компонент
argument-hint: [имя компонента] [--typescript]

---

Создай React компонент "$1":

1. Файл в `src/components/$1/`
2. Функциональный компонент с хуками
3. PropTypes или TypeScript (если флаг --typescript)
4. Файл стилей $1.module.css
5. Экспорт через index.js
6. Storybook история
7. Базовые тесты

Используй современные best practices.
```

**Использование:**

```
/component UserProfile --typescript
```

### Пример 3: Команда для вайбкодера

**Файл:** `.claude/commands/scenario/index.js`

```markdown
---
name: scenario
description: Генерация вирусного сценария для Reels
argument-hint: [тема] [--tts]

---

{{#if $1}}
Создай уникальный вирусный сценарий для Instagram Reels на тему: **$1**

**Структура:**

1. 🎣 Хук (3 секунды) - вызвать эмоцию
2. 😣 3 боли целевой аудитории
3. ✅ 3 конкретных преимущества решения
4. 📞 Сильный призыв к действию

**Требования:**

- Длительность: 30 секунд
- Стиль: энергичный, дерзкий
- Целевая аудитория: предприниматели 25-40 лет
- Уникальность: каждый раз новый контент

**Формат вывода:**

- Текст сценария
- Тайминги для каждого блока
- Рекомендации по визуалу

{{#if (eq $2 "--tts")}}
**Дополнительно:** Оптимизируй текст для озвучки TTS

- Конвертируй числа в слова (1000 → тысяча)
- Убери сложные термины
- Добавь паузы через запятые
  {{/if}}

Сохрани результат в `assets/scripts/scenario-{{timestamp}}.txt`
{{else}}
❌ Укажите тему для сценария: `/scenario "ваша тема"`
Пример: `/scenario "нейросети для бизнеса" --tts`
{{/if}}
```

**Использование:**

```
/scenario "нейросети для бизнеса" --tts
```

## Передача аргументов: Делаем команды гибкими

### Базовый синтаксис

```markdown
$ARGUMENTS - все аргументы целиком
$1 - первый аргумент
$2 - второй аргумент
$3 - третий аргумент
... и так далее
```

### Условная логика

**Проверка наличия аргумента:**

```markdown
{{#if $1}}
Выполнить действие с $1
{{else}}
Показать сообщение об ошибке
{{/if}}
```

**Проверка флага:**

```markdown
{{#if (eq $2 "--verbose")}}
Детальный вывод
{{else}}
Краткий вывод
{{/if}}
```

### Множественные аргументы

**Пример:** `.claude/commands/api/index.js`

```markdown
---
name: api
description: Создать API endpoint
argument-hint: [метод] [путь] [--auth]

---

Создай $1 endpoint для пути "$2":

**Файлы:**

1. Route: `routes/$2.routes.js`
2. Controller: `controllers/$2.controller.js`
3. Service: `services/$2.service.js`
4. Validation: `validation/$2.validation.js`

{{#if (eq $3 "--auth")}}
**Добавить:**

- JWT middleware для аутентификации
- Проверку прав доступа
  {{/if}}

**Тесты:**

- Unit тесты для сервиса
- Integration тесты для endpoint
```

**Использование:**

```
/api POST users/register --auth
```

### Значения по умолчанию

```markdown
**Приоритет:** {{#if $3}}$3{{else}}normal{{/if}}
```

Если `$3` не указан - используется "normal".

## Frontmatter и конфигурация

### Обязательные поля

```yaml
---
name: command-name # Имя команды (без /)
description: Описание # Когда использовать
---
```

### Опциональные поля

```yaml
---
name: advanced-command
description: Продвинутая команда
argument-hint: [arg1] [arg2] [--flag]    # Подсказка по аргументам
tools: Read, Write, Bash, Grep           # Доступные инструменты
model: sonnet                             # Модель Claude (sonnet/opus)
---
```

### Инсайт: argument-hint

`argument-hint` - это не просто комментарий. Это **контракт** между вами и командой.

**Хороший hint:**

```yaml
argument-hint: [тема сценария] [--tts] [--verbose]
```

**Плохой hint:**

```yaml
argument-hint: параметры
```

Хороший hint делает команду самодокументируемой.

## Best Practices создания команд

### 1. Одна команда - одна ответственность

**Плохо:**

```markdown
/do-everything - делает всё что угодно
```

**Хорошо:**

```markdown
/scenario - генерирует сценарии
/avatar - создаёт видео
/test - пишет тесты
```

### 2. Валидация входных данных

**Всегда проверяй аргументы:**

```markdown
{{#if $1}}
Выполнить команду
{{else}}
❌ Ошибка: укажите аргумент
Пример: /command "значение"
{{/if}}
```

### 3. Понятные сообщения об ошибках

**Плохо:**

```
Ошибка
```

**Хорошо:**

```
❌ Укажите тему для сценария
Пример: /scenario "нейросети"
Доступные опции: --tts, --verbose
```

### 4. Документируй поведение

```markdown
---
name: complex-command
description: Сложная команда
---

#Эта команда делает:
#1. Анализирует входные данные
#2. Генерирует код
#3. Создаёт тесты
#4. Обновляет документацию

#Аргументы:
#$1 - название модуля
#$2 - тип (api|ui|service)
#$3 - флаги (--test, --doc)
```

### 5. Переиспользование логики

**Создавай вспомогательные команды:**

```
/setup-api - использует /component + /test + /document
```

## Типичные ошибки

### Ошибка 1: Забытые кавычки

```bash
❌ /scenario нейросети для бизнеса
✅ /scenario "нейросети для бизнеса"
```

Без кавычек Claude видит только "нейросети" как $1.

### Ошибка 2: Неправильный порядок аргументов

```markdown
argument-hint: [тема] [--flag]
```

```bash
❌ /command --flag "тема"
✅ /command "тема" --flag
```

### Ошибка 3: Отсутствие проверок

```markdown
❌ Выполнить операцию с $1
✅ {{#if $1}}Выполнить{{else}}Ошибка{{/if}}
```

### Ошибка 4: Слишком общие команды

```markdown
❌ /do - сделай что-нибудь
✅ /optimize - оптимизируй производительность
```

## Философский инсайт: Язык намерений

**Slash команды - это ваш собственный язык программирования для общения с Claude.**

Традиционные языки программирования:

```javascript
function createComponent(name, type) { ... }
```

Ваш язык команд:

```
/component "UserProfile" --typescript
```

Разница? В традиционном коде вы описываете **КАК** делать.
В slash командах вы описываете **ЧТО** нужно получить.

**Вы не программируете алгоритмы - вы программируете намерения.**

## Упражнения для практики

### Упражнение 1: Базовая команда

Создай команду `/hello`, которая приветствует пользователя по имени.

```
/hello Александр
→ Привет, Александр! Чем могу помочь?
```

### Упражнение 2: Команда с условиями

Создай команду `/greet [имя] [--formal]`, которая:

- Без флага: неформальное приветствие
- С флагом `--formal`: официальное обращение

### Упражнение 3: Рабочая команда

Создай команду для твоей реальной работы. Например:

- Генерация контента
- Проверка кода
- Создание структуры проекта

### Упражнение 4: Команда с пост-обработкой

Создай команду, которая:

1. Генерирует контент
2. Сохраняет в файл
3. Конвертирует в другой формат
4. Отправляет отчёт

### Упражнение 5: Цепочка команд

Создай 3 команды, которые работают вместе:

```
/init "project"    - инициализация
/add "feature"     - добавление функций
/finalize          - финализация
```

## Словарь терминов

- **Slash команда** - пользовательская команда начинающаяся с `/`
- **Frontmatter** - метаданные в начале файла между `---`
- **argument-hint** - подсказка о том, какие аргументы принимает команда
- **Handlebars** - система шаблонов для условной логики `{{#if}}`
- **Pipeline** - последовательность этапов обработки
- **TTS** (Text-to-Speech) - преобразование текста в речь

### Задание 3: Библиотека команд для команды (50-60+ минут)

**Цель:** Разработать переиспользуемую библиотеку команд для вашей команды или проекта.

**Задача:**

Создайте набор из **минимум 10 взаимосвязанных команд**, которые покрывают весь жизненный цикл разработки:

**Категория 1: Инициализация (2 команды)**

- `/init [тип-проекта]` - создание структуры проекта
- `/setup [окружение]` - настройка окружения (dev/staging/prod)

**Категория 2: Разработка (3 команды)**

- `/feature [название]` - создание новой фичи (файлы + тесты + документация)
- `/api [метод] [путь]` - создание API endpoint
- `/ui [компонент]` - создание UI компонента

**Категория 3: Качество (3 команды)**

- `/test [файл]` - генерация тестов
- `/review [файл]` - code review
- `/refactor [файл]` - рефакторинг

**Категория 4: Деплой (2 команды)**

- `/deploy [окружение]` - чек-лист деплоя
- `/rollback [версия]` - откат версии

**Дополнительные требования:**

1. **Единый стиль:**

   - Консистентные названия команд
   - Одинаковый формат argument-hint
   - Унифицированная обработка ошибок

2. **Документация:**

   - Создайте `docs/slash-commands.md`
   - Для каждой команды: описание, синтаксис, примеры
   - Схема взаимосвязей команд

3. **Интеграция:**

   - Команды должны работать вместе
   - Например: `/init` создаёт структуру, `/feature` использует эту структуру
   - Команды сохраняют метаданные для других команд

4. **Качество:**
   - Все команды с валидацией
   - Понятные ошибки
   - Примеры использования в коде

**Структура проекта:**

```
.claude/
  commands/
    init/index.js
    setup/index.js
    feature/index.js
    api/index.js
    ui/index.js
    test/index.js
    review/index.js
    refactor/index.js
    deploy/index.js
    rollback/index.js

docs/
  slash-commands.md           # Полная документация
  commands-architecture.md    # Архитектура и взаимосвязи
  examples/                   # Примеры использования
```

**Критерии выполнения:**

- ✅ Минимум 10 работающих команд
- ✅ Полная документация всех команд
- ✅ Команды интегрированы друг с другом
- ✅ Единый стиль и подход
- ✅ Протестированы все сценарии использования

**Тестирование:**

Пройдите полный цикл:


Каждый шаг должен работать и переходить к следующему.

**Бонус задания:**

2. **Конфигурация:** Добавьте `.claude/config.json` для настройки путей и дефолтных значений
