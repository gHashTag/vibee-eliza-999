**Предыдущий контекст:** В [10-MCP-ПРОТОКОЛ.md](10-MCP-ПРОТОКОЛ.md) вы научились подключать внешние сервисы к Claude. Теперь изучим продвинутые техники, которые сделают вас настоящим вайбкодером.

## 🎯 Что такое "Продвинутые техники"?

Это не сложные штуки для гениев. Это **простые приёмы, которые экономят ваше время**.

Представьте:

- Вместо 2 часов ручной проверки кода — 30 секунд автоматической
- Вместо одного агента — целая команда работает параллельно
- Вместо ручной работы — всё само делается в фоне

**Вот это и есть продвинутые техники.**

---

## 1️⃣ Headless режим (автоматизация)

### 🏠 Аналогия из жизни

Обычный Claude Code — это как помощник, с которым вы разговариваете:

- Вы: "Проверь этот код"
- Claude: делает, отвечает
- Вы: "Теперь создай тесты"
- Claude: делает, отвечает

**Headless режим** — это как робот-пылесос:

- Вы настроили один раз
- Он сам ездит и убирает
- Вы занимаетесь своими делами

### 💡 Зачем вайбкодеру?

**Проблема:** Каждый день нужно проверять код перед коммитом — скучно и долго.

**Решение:** Настроить автоматическую проверку.

### Простой пример

```bash
# Вместо интерактивной работы с Claude:
claude

# Запускаем команду сразу (headless):
claude --headless "Проверь все файлы в src/ на ошибки"
```

### ✅ Результат

Вы запускаете одну команду, Claude проверяет всё и выдаёт отчёт. **Экономия: 15 минут каждый день.**

### 🎯 Когда использовать headless

1. **Перед каждым коммитом** — автоматическая проверка
2. **Ночью** — анализ всего проекта пока вы спите
3. **В CI/CD** — автоматические проверки в GitHub/GitLab
4. **Batch обработка** — проверить сразу 50 файлов

## 2️⃣ Параллельные субагенты

### 🏠 Аналогия из жизни

**Последовательная работа:**

```
Вы делаете backend → потом frontend → потом тесты → потом документацию
Время: 4 часа
```

**Параллельная работа (субагенты):**

```
Агент 1: Backend  ────┐
Агент 2: Frontend ────┤ → всё готово одновременно
Агент 3: Тесты    ────┤
Агент 4: Документация ─┘
Время: 1 час
```

### 💡 Зачем вайбкодеру?

**Проблема:** Фича требует изменений в backend, frontend, тестах, документации. Делать по очереди — медленно.

**Решение:** Запустить всех агентов параллельно.

### Как это работает

```javascript
// Запускаем 4 агента одновременно
Task("Backend dev: создай API для авторизации", "backend-dev");
Task("Frontend dev: создай форму логина", "coder");
Task("Tester: напиши тесты для API", "tester");
Task("Documenter: документируй API", "api-docs");

// Все работают параллельно!
```

### ✅ Результат

Вместо 4 часов последовательной работы — **1 час параллельной**.

Субагенты координируются через Claude Flow Memory:

- Backend агент создал API → сохранил информацию в память
- Frontend агент прочитал из памяти → создал форму
- Tester прочитал из памяти → написал тесты

## 3️⃣ CI/CD интеграция

### 🏠 Аналогия из жизни

**Без CI/CD:**

```
Вы пишете код → забываете проверить → пушите → всё ломается → стыдно
```

**С CI/CD:**

```
Вы пишете код → пушите → робот автоматически проверяет → находит ошибку ДО того как всё сломалось
```

### 💡 Зачем вайбкодеру?

**Проблема:** Забываете запускать тесты перед коммитом → баги попадают в продакшн.

**Решение:** Автоматическая проверка каждого Pull Request.

### Простой пример (GitHub Actions)

Создайте файл `.github/workflows/claude-check.yml`:

```yaml
name: Claude Code Check

on: [pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Check code with Claude
        run: |
          claude --headless "Проверь изменения в этом PR на ошибки"
```

### ✅ Результат

Теперь при каждом PR GitHub автоматически проверяет код через Claude. **Больше никаких стыдных багов в продакшне.**

## 4️⃣ Оптимизация для больших проектов

### 🏠 Аналогия из жизни

**Плохо:** Каждый раз искать нужный файл среди 10,000 файлов вручную.

**Хорошо:** Создать индекс (как в библиотеке) — найти книгу за секунду.

### 💡 Зачем вайбкодеру?

**Проблема:** Проект большой (1000+ файлов). Claude долго ищет нужный код.

**Решение:** Создать индекс проекта один раз.

### Простой пример

```bash
# Создать индекс всех файлов проекта
claude --headless "Проиндексируй все файлы в src/ и сохрани в .claude/index.json"
```

Теперь Claude будет находить код мгновенно, используя индекс вместо поиска по всем файлам.

### ✅ Результат

Поиск в проекте: **было 30 секунд → стало 2 секунды**.

## 5️⃣ Best Practices (коротко)

### ✅ Что НУЖНО делать

1. **Используйте .context.md** — один раз напишите правила, Claude будет следовать
2. **Batch операции** — лучше обработать 10 файлов сразу, чем по одному
3. **Логируйте важное** — сохраняйте результаты работы в файлы
4. **Тестируйте автоматизацию** — перед продакшном проверьте на тестовом проекте

### ❌ Что НЕ НУЖНО делать

1. **Не делайте всё руками** — если делаете больше 2 раз, автоматизируйте
2. **Не храните секреты в коде** — используйте .env файлы
3. **Не игнорируйте ошибки** — Claude их показывает не просто так
4. **Не усложняйте** — начинайте с простого, усложняйте только если нужно

## 6️⃣ Monitoring и Debug

### 🏠 Аналогия из жизни

**Без мониторинга:**

```
Что-то сломалось → не знаете где → паника → час на поиск проблемы
```

**С мониторингом:**

```
Что-то сломалось → смотрите логи → сразу видите проблему → 5 минут на фикс
```

### 💡 Зачем вайбкодеру?

**Проблема:** Скрипт упал ночью, вы не знаете почему.

**Решение:** Логирование в файл.

### Простой пример

```javascript
// Вместо console.log
console.log("Что-то делаю...");

// Логируйте в файл
const log = require("fs").appendFileSync;
log("debug.log", `[${new Date()}] Что-то делаю...\n`);
```

### ✅ Результат

Теперь вы всегда знаете, что произошло и когда.

### Блок 4: Monitoring и Debug

**Вопрос 9:** Как правильно логировать в production системе?

- A) console.log в stdout
- B) Записывать в файлы с timestamp
- C) Не логировать, использовать только debugger
- D) Отправлять все логи в Telegram

<details>
<summary>Ответ</summary>

**B) Записывать в файлы с timestamp**

Production логирование должно быть:

- Постоянным (файлы с ротацией)
- Структурированным (timestamp, level, context)
- Фильтруемым (error, warn, info, debug)
- Безопасным (не логировать секреты)

Пример:

```javascript
const fs = require("fs");
const log = (level, message) => {
  const entry = `[${new Date().toISOString()}] [${level}] ${message}\n`;
  fs.appendFileSync("app.log", entry);
};
```

</details>

**Вопрос 10:** Какие метрики критично отслеживать при использовании параллельных агентов?

- A) Только время выполнения
- B) Время выполнения и потребление памяти
- C) Время, память, количество токенов, ошибки
- D) Только количество ошибок

<details>
<summary>Ответ</summary>

**C) Время, память, количество токенов, ошибки**

Для production важно отслеживать:

- ⏱️ **Время выполнения** — находить bottleneck'и
- 💾 **Память** — предотвращать OOM
- 🪙 **Токены** — контролировать затраты
- ❌ **Ошибки** — отлавливать проблемы
- 🔄 **Retry rate** — оценивать стабильность

Claude Flow предоставляет все эти метрики через:

```bash
npx claude-flow@alpha hooks session-end --export-metrics true
```

</details>

   ```javascript
   // .claude/workflows/feature-pipeline.js
   const { Task } = require("claude-code");
   const { memory } = require("claude-flow");

   async function developFeature(featureDescription) {
     // 1. Генерация спецификации
     const spec = await Task(
       "Specification agent: создай детальную спеку для: " + featureDescription,
       "specification",
     );

     // Сохранить в память для других агентов
     await memory.store("current-feature-spec", spec);

     // 2. Параллельная разработка
     const [backend, frontend, tests, docs] = await Promise.all([
       Task("Backend agent: реализуй API по спеке из памяти", "backend-dev"),
       Task("Frontend agent: создай UI по спеке из памяти", "coder"),
       Task("Test agent: напиши тесты по спеке из памяти", "tester"),
       Task("Doc agent: создай документацию по спеке", "api-docs"),
     ]);

     // 3. Code review
     const review = await Task(
       "Reviewer: проверь весь код на качество и безопасность",
       "reviewer",
     );

     // 4. Integration
     if (review.approved) {
       await Task("Integration agent: собери всё вместе", "system-architect");
       return {
         status: "ready_for_deploy",
         artifacts: [backend, frontend, tests, docs],
       };
     } else {
       return { status: "needs_fixes", issues: review.issues };
     }
   }

   module.exports = { developFeature };
   ```

   ```javascript
   // .claude/monitoring/metrics-collector.js
   const fs = require("fs");

   class MetricsCollector {
     constructor() {
       this.metrics = {
         features_developed: 0,
         avg_development_time: 0,
         code_quality_score: 0,
         tests_coverage: 0,
         time_saved_hours: 0,
       };
     }

     async recordFeature(startTime, endTime, quality, coverage) {
       const duration = (endTime - startTime) / 1000 / 60; // минуты

       this.metrics.features_developed++;
       this.metrics.avg_development_time =
         (this.metrics.avg_development_time + duration) / 2;
       this.metrics.code_quality_score =
         (this.metrics.code_quality_score + quality) / 2;
       this.metrics.tests_coverage = coverage;

       // Экономия: ручная разработка ~4 часа, автомат ~1 час
       this.metrics.time_saved_hours += 3;

       this.save();
     }

     save() {
       fs.writeFileSync(
         ".claude/monitoring/metrics.json",
         JSON.stringify(this.metrics, null, 2),
       );
     }

     generateReport() {
       return `
       # Development Metrics Report
   
       - Фич разработано: ${this.metrics.features_developed}
       - Среднее время: ${this.metrics.avg_development_time.toFixed(1)} мин
       - Качество кода: ${this.metrics.code_quality_score.toFixed(1)}/10
       - Покрытие тестами: ${this.metrics.tests_coverage}%
       - Сэкономлено времени: ${this.metrics.time_saved_hours} часов
       `;
     }
   }

   module.exports = MetricsCollector;
   ```
